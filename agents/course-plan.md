# CSE122 --- Course Plan

**Học phần:** Phát triển ứng dụng Web cơ bản (Basic Web Application
Development)\
**Mã học phần:** CSE122\
**Tổ chức:** 10 Lecture sessions × 3 periods + 5 Practice sessions × 3
periods\
**Tổng:** 30 periods Lecture + 15 periods Practice = 45 periods\
**Thời lượng mỗi period:** 55 phút\
**Ngôn ngữ:** Tiếng Việt; giữ các technical keywords/concepts phổ biến
bằng English.

## 1. Course Organization

Khóa học gồm hai loại buổi riêng biệt:

-   **Lecture --- 10 sessions × 3 periods:** tập trung vào concepts,
    visual explanation, instructor demo, code demonstration và Q&A.
    Lecture không phụ thuộc vào việc mỗi sinh viên có laptop.
-   **Practice --- 5 sessions × 3 periods:** giảng viên giới thiệu ngắn
    nội dung thực hành, demo bài mẫu, sau đó sinh viên thực hiện
    exercises/mini tasks và phát triển dần project.

Nội dung bám theo 9 chapters của syllabus:

**Web Foundations → Semantic HTML → CSS → Responsive UI/Bootstrap →
JavaScript → DOM/Events → Async → REST/Fetch → Component Thinking &
Integration**

### Teaching approach

Trong Lecture, ưu tiên:

**Concept → Visual → Instructor Demo → Discussion/Q&A → Review**

Không yêu cầu sinh viên phải thực hành trực tiếp trong Lecture. Student
exercises được tổ chức trong các Practice sessions.

Trong Practice, ưu tiên:

**Brief Introduction → Instructor Demo → Guided Exercise → Student
Practice → Review**

### Demo Interpretation Rule

References such as "Instructor demo", "Instructor coding demo" or
"Complete instructor demo" in this course plan define teaching activities,
not literal slide text.

When generating student-facing slides:
- present the demo as what students will observe or learn;
- never display instructions addressed to the instructor;
- place instructor procedures in `teaching-notes.md`.

Example:

Course plan:
`Instructor demo: quan sát Box Model bằng DevTools`

Student slide:
`Demo: Quan sát Box Model bằng DevTools`

Teaching notes:
Detailed instructor procedure and talking points.

# 9. Lecture Slide & Demo Production Contract

## 9.1 No fixed slide count

Không đặt quota cố định như 20, 25 hay 30 slides cho một Lecture.

Mỗi Lecture có **3 periods × 55 phút = 165 phút**. Số slide phụ thuộc vào nội dung và cách giải thích. Một Lecture có thể có **30–50+ slides** khi cần. Lecture 01 đặc biệt có thể cần khoảng **40–50+ slides** vì bao gồm course introduction, Web foundations, architecture, HTTP, tools, DevTools và Git/GitHub.

Không thêm slide chỉ để tăng số lượng; cũng không ghép nhiều concepts quan trọng vào một slide chỉ để giảm số lượng.

## 9.2 What deserves its own slide

Tách slide khi việc tách giúp sinh viên hiểu rõ hơn, đặc biệt với:
- concept/definition quan trọng
- architecture/flow diagram
- comparison
- code example
- command + explanation
- tool introduction
- screenshot/tool interface
- step-by-step instructor demo
- common mistake/debugging example
- worked example

Một slide thông thường nên có **một teaching idea chính**.

## 9.3 Commands must be teachable

Khi dùng terminal, Git hoặc command-line tool, không chỉ liệt kê command. Với command quan trọng cần làm rõ:

```text
Command → Purpose → Syntax → Example → Expected result → When/why to use it
```

Có thể nhóm commands đơn giản có liên quan nếu vẫn rõ và đọc tốt trên projector.

## 9.4 Tools must be demonstrated, not merely named

Khi giới thiệu tool, cần mô tả:
- tool dùng để làm gì
- vị trí trong Web development workflow
- thao tác chính cần biết
- ví dụ/demo cụ thể

Các tool xuyên suốt course:
- VS Code
- Browser
- Chrome DevTools
- Terminal / PowerShell
- Local Web server
- Git
- GitHub
- HTML Validator
- Bootstrap documentation
- Responsive/device tools
- Network inspection khi làm HTTP/API

Không cần dạy toàn bộ tool; chỉ dạy phần cần cho learning outcome hiện tại.

## 9.5 Code and demo slides

Code phải:
- đủ lớn để đọc trên projector
- ngắn và tập trung vào concept
- có syntax hợp lệ
- có output/result khi hữu ích
- ưu tiên example chạy được
- đi theo simple → explain → demonstrate → extend

Demo phức tạp nên chia thành nhiều bước/slides thay vì đặt toàn bộ source code lên một slide.

## 9.6 Visual explanation

Ưu tiên purpose-built visuals cho client-server, HTTP, URL anatomy, HTML structure, CSS box model, Flexbox/Grid, responsive breakpoints, DOM tree, event bubbling, event loop, REST API, component tree và Git workflow.

Visual phải chính xác về kỹ thuật và đọc được trên projector.

Do not create independent or disconnected lecture websites.
